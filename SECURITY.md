# Security policy

Security fixes target the latest released version and the `main` branch.
Backports to older releases are not guaranteed.

## Report privately

Do not disclose a suspected vulnerability in a public issue. Use **Report a
vulnerability** in the repository's GitHub Security tab when available.
Otherwise, contact a maintainer privately through the contact options on their
GitHub profile.

Provide the affected release or commit, a minimal reproduction, the environment,
the likely impact, and any mitigation you have identified. For a native-memory
issue, include the relevant array shapes, dtypes, strides, and operations.
Share only information necessary to reproduce and understand the problem.

## Response and disclosure

The project aims to acknowledge reports within seven days. Allow time to
reproduce the issue, develop and validate a fix, and coordinate disclosure
before publishing details. Include a private contact route so maintainers can
request clarification.

Ordinary numerical inaccuracies and installation questions belong in the
[public support process](SUPPORT.md) unless they create a security impact.
Conduct concerns follow the [Code of Conduct](CODE_OF_CONDUCT.md).
